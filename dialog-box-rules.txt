ARCHETYPE A — SKETCHY RECTANGLE
Shape

Base form: Rectangle with very slight corner rounding (rx="6" ry="6")
Aspect ratio: Roughly 2.2 : 1 (wide landscape)
Dimensions (reference): ~200 × 90 px
Stroke style: Double-traced rough line simulating a hand-drawn look

Achieved by drawing the rect twice with slight x/y offsets (1–2px) and varying stroke-dasharray to break up regularity
stroke-width="2.5" on outer, stroke-width="1.5" on inner
Both strokes: stroke="#1a1a1a" (near-black, not pure black)
fill="white" or fill="none" with white background assumed



Tail (speech pointer)

Shape: Flat triangle extending from the bottom-left of the box
Attachment point: Roughly 20–30% from the left edge of the bottom side
Direction: Points down and slightly left at ~220° from 12 o'clock
Tail length: ~25–35% of box height
Tail base width: ~25–30px at attachment point
Tail tip: Comes to a sharp point
SVG construction:

Polygon or path with 3 points:
  P1 = (box_x + 30, box_bottom)       ← left attachment
  P2 = (box_x + 55, box_bottom)       ← right attachment  
  P3 = (box_x + 15, box_bottom + 30)  ← tip (down-left)

The tail is drawn with the same sketchy double-stroke as the box body

Full SVG Recipe (Archetype A)

  <!-- Outer rough stroke pass -->
  <rect x="12" y="10" width="218" height="90" rx="6" ry="6"
        fill="white" stroke="#1a1a1a" stroke-width="3"
        stroke-dasharray="4,1,6,1,3,2,5,1"/>
  <!-- Inner rough stroke pass (offset by 2px) -->
  <rect x="14" y="12" width="214" height="86" rx="5" ry="5"
        fill="none" stroke="#1a1a1a" stroke-width="1.5"
        stroke-dasharray="6,2,3,1,5,2"/>
  <!-- Tail triangle -->
  <polygon points="38,100 63,100 22,130"
           fill="white" stroke="#1a1a1a" stroke-width="2.5"/>
</svg>

ARCHETYPE B — CLEAN ROUNDED RECTANGLE
Shape

Base form: Rectangle with large corner rounding (rx="30" ry="30")
Aspect ratio: ~1.4 : 1 (moderately wide, nearly square)
Dimensions (reference): ~190 × 140 px
Stroke style: Single clean line, stroke-width="2.0", stroke="#111111", fill="white"
The large radius makes corners appear almost circular — box looks "pillow" shaped

Tail (speech pointer)

Shape: Narrow isoceles triangle
Attachment point: Bottom-center of the box (±10px from horizontal midpoint)
Direction: Straight downward, perpendicular to bottom edge
Tail length: ~20–28% of box height (shorter and more discreet than A)
Tail base width: ~20px
Tail tip: Sharp point directly below center
SVG construction:

P1 = (cx - 12, box_bottom)   ← left of center
P2 = (cx + 12, box_bottom)   ← right of center
P3 = (cx,      box_bottom + 32) ← tip straight down

Tail merges cleanly into the bottom edge — where tail meets box, those two points sit on the rounded-rect border so no gap or overlap shows

Full SVG Recipe (Archetype B)
svg<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 220 200" width="220" height="200">
  <!-- Main bubble body -->
  <rect x="15" y="10" width="190" height="145" rx="30" ry="30"
        fill="white" stroke="#111111" stroke-width="2"/>
  <!-- Tail -->
  <polygon points="98,155 122,155 110,187"
           fill="white" stroke="#111111" stroke-width="2"/>
  <!-- Cover seam between tail base and box bottom -->
  <line x1="98" y1="155" x2="122" y2="155"
        stroke="white" stroke-width="3"/>
</svg>

The white cover line over the tail base erases the box border between the two attachment points, making the tail appear to flow out of an opening rather than overlap.


ARCHETYPE C — CLOUD / THOUGHT BUBBLE
Shape

Base form: Organic silhouette built from 8–12 overlapping circles of varying radii
Construction method: Place circles so each overlaps its neighbors by ~40% of the smaller circle's radius; the union forms the cloud outline
Typical radii range: 20px–40px per bump circle
Overall bounding box: ~180 × 110 px (wide landscape)
Stroke: Single clean stroke-width="2", stroke="#111111", fill="white"

Bump circle placement (reference cloud, 10 bumps)
Bump centers (cx, cy, r) — relative to cloud top-left corner (0,0):
  1.  (35,  55, 28)   ← left side
  2.  (60,  35, 30)   ← upper-left
  3.  (90,  22, 28)   ← upper-mid-left
  4.  (120, 18, 32)   ← top-center
  5.  (152, 24, 26)   ← upper-mid-right
  6.  (175, 40, 24)   ← upper-right
  7.  (188, 62, 22)   ← right side
  8.  (175, 82, 26)   ← lower-right
  9.  (100, 90, 30)   ← bottom-center
 10.  (45,  80, 26)   ← lower-left

Render as a <path> using arc segments tracing only the outer convex portions of each circle
Alternatively, render all circles with fill="white" and the same stroke, then draw them in order so each partially covers the previous — but this leaves interior stroke lines visible. Prefer the unified path approach.

Unified path approach
Use SVG <path> with arc commands that trace the outer silhouette:
For each exposed arc of bump circle i:
  A {r} {r} 0 {large-arc} 1 {x_end} {y_end}
This requires computing the intersection angles between adjacent circles — complex but produces the cleanest result.
Thought bubble tail

NOT a triangle — consists of 2–3 small circles descending from the bottom-left of the cloud
Circle sizes: progressively smaller going away from the cloud

Circle 1 (closest): r ≈ 10px
Circle 2: r ≈ 7px
Circle 3 (farthest/tip): r ≈ 4px


Direction: Diagonally down-left at ~225° from cloud center
Spacing: Each circle's edge just touches or very slightly overlaps the previous

Cloud bottom-left region anchor ≈ (40, 95)
Bubble 1: cx=32, cy=108, r=10
Bubble 2: cx=22, cy=120, r=7
Bubble 3: cx=14, cy=130, r=4

ARCHETYPE D — OVAL / ELLIPSE
Shape

Base form: Pure <ellipse>, no corners
Aspect ratio: ~2.5 : 1 (wide, squat ellipse)
Dimensions (reference): ~220 × 90 px (rx=110, ry=45)
Stroke: Single clean stroke-width="2.5", stroke="#111111", fill="white"

Tail (speech pointer)

Shape: Narrow triangle, same as Archetype B
Attachment point: Bottom-center of the ellipse
Direction: Straight down or very slightly left
Tail length: ~30–35% of ellipse height (proportionally longer than B because ellipse is shorter)
Tail base width: ~18–22px
The tail attaches where the ellipse border crosses the bottom, so compute the actual ellipse point:

At angle 270° (straight down): x = cx, y = cy + ry
Attachment pts: (cx−10, cy+ry) and (cx+10, cy+ry)
Tip: (cx, cy + ry + tail_length)

UNIVERSAL RULES FOR ALL DIALOG BOXES
Seam hiding (tail-to-body join)
Every tail shares two points with the body outline. Draw a white stroke line connecting those two points, same width as the body stroke + 1px, to erase the body border between them and create an open "mouth."

THE CORE PRINCIPLE
A speech bubble must be drawn as one closed path that traces the body outline AND detours into the tail, treating the tail's two attachment points as part of the body's perimeter. The pen never lifts. No overlapping shapes, no masking lines.

ARCHETYPE B — CORRECTED (Rounded Rectangle)
The single-path construction
The path traces the perimeter in one continuous stroke. Where the bottom edge would normally run straight across, we detour downward into the tail and back up.
Path breakdown (rounded rectangle with tail)
Given: rectangle at (x, y) with width=W, height=H, corner radius r, tail base centered at cx with half-width tw, tail tip at (tipX, tipY).
Start at top-left corner (after the rounded curve begins):
M (x+r) y

Top edge:
L (x+W-r) y

Top-right corner:
A r r 0 0 1 (x+W) (y+r)

Right edge:
L (x+W) (y+H-r)

Bottom-right corner:
A r r 0 0 1 (x+W-r) (y+H)

Bottom edge — RIGHT half, stop at tail's right attachment:
L (cx+tw) (y+H)

DETOUR INTO TAIL — down to tip, then back up:
L tipX tipY
L (cx-tw) (y+H)

Bottom edge — LEFT half, continue to corner:
L (x+r) (y+H)

Bottom-left corner:
A r r 0 0 1 x (y+H-r)

Left edge:
L x (y+r)

Top-left corner:
A r r 0 0 1 (x+r) y

Close:
Z
Worked example
Rectangle: x=15, y=10, W=190, H=145, r=30
Tail: cx=110, tw=12, tipX=110, tipY=187

Why this works: The path enters the tail at (122, 155), descends to the tip (110, 187), returns to (98, 155), then continues along the bottom edge. The body and tail share a single stroke — no seam exists because there's no boundary between them.

ARCHETYPE D — CORRECTED (Oval / Ellipse)
This one is trickier because an ellipse has no flat edge to interrupt. We construct it from two elliptical arcs that meet at the tail's attachment points, with the tail as straight line segments between them.
Path breakdown
Given: ellipse centered at (cx, cy) with radii rx, ry. Tail attaches at two points on the lower curve of the ellipse, symmetric about cx.
Step 1 — choose tail attachment angle θ from horizontal:
For a narrow tail, θ ≈ 75–85° below horizontal (close to the bottom).
Step 2 — compute the two attachment points on the ellipse:
Right attachment:  (cx + rx·cos(−θ), cy + ry·sin(θ))   ... using θ measured from +x axis downward
Left attachment:   (cx − rx·cos(−θ), cy + ry·sin(θ))
In SVG terms, if you parametrize the ellipse by angle φ from center (with 0° = right, 90° = down):
P_right = (cx + rx·cos(φ),  cy + ry·sin(φ))
P_left  = (cx + rx·cos(180°−φ), cy + ry·sin(180°−φ))
       = (cx − rx·cos(φ),  cy + ry·sin(φ))
Step 3 — the path: trace from P_left, clockwise around the top, to P_right, then detour through the tail, back to P_left.
M P_right.x P_right.y
A rx ry 0 1 0 P_left.x P_left.y     ← large arc clockwise around the TOP
L tipX tipY                          ← down to tail tip
L P_right.x P_right.y                ← back up to right attachment
Z
Wait — that traces backward. Let me redo cleanly:
M P_left.x P_left.y
A rx ry 0 1 1 P_right.x P_right.y    ← arc going clockwise around the top
                                        (large-arc=1, sweep=1)
L tipX tipY                           ← tail right side → tip
L P_left.x P_left.y                   ← tail tip → left attachment
Z
Worked example
Ellipse: cx=130, cy=70, rx=112, ry=50
Choose φ = 80° (attachment near the bottom, narrow gap):
cos(80°) ≈ 0.1736
sin(80°) ≈ 0.9848

P_right = (130 + 112·0.1736,  70 + 50·0.9848) = (149.4, 119.2)
P_left  = (130 − 112·0.1736,  70 + 50·0.9848) = (110.6, 119.2)
Tail tip = (130, 148)

  <path d="M 110.6 119.2
           A 112 50 0 1 1 149.4 119.2
           L 130 148
           L 110.6 119.2
           Z"
        fill="white" stroke="#111111" stroke-width="2.5"
        stroke-linejoin="round"/>
</svg>
Why this works: The arc traces from left attachment, clockwise over the top of the ellipse, down to the right attachment. Two straight lines form the tail. The closing Z is redundant since the last L already returns to the start, but it's safe to include.

ARCHETYPE C — CORRECTED (Cloud)
The cloud body should also be a single path tracing the outer silhouette of overlapping circles via A arc commands. The thought-tail bubbles remain separate (they're meant to be detached) — that's authentic to thought-bubble convention, not a flaw.
Cloud body path principle
For each adjacent pair of bump circles (C_i, C_{i+1}):

Find the two intersection points of the two circles
The outer intersection point is where the outline transitions from C_i to C_{i+1}
Trace an arc on C_i from the previous transition to this one, using its radius

Path: M (first transition point)
For each bump i:
  A r_i r_i 0 0 1 (transition_to_next)
Z
Computing intersection points
For two circles with centers (x₁,y₁), (x₂,y₂) and radii r₁, r₂:
d = distance between centers
a = (r₁² − r₂² + d²) / (2d)
h = √(r₁² − a²)
midpoint M = (x₁ + a·(x₂−x₁)/d,  y₁ + a·(y₂−y₁)/d)
intersections = M ± h·(perpendicular unit vector)
Pick the intersection on the outside of the cloud (farther from the cloud's centroid).
Practical shortcut
For training purposes, precompute the transition points for a canonical 9-bump cloud and store them as a reusable path. The model doesn't need to compute intersections on the fly — it just emits the fixed path with parameterized scale and tail position.

UPDATED UNIVERSAL RULES

Body and tail are ONE path. Never draw the body and tail as separate elements. Never use white lines to mask seams.
The path enters the tail through the body's perimeter. The detour replaces a segment of the body outline rather than overlapping it.
Use stroke-linejoin="round" at sharp corners to avoid mitered spikes at the tail base.
Cloud body is a single path of arcs. The thought-tail bubbles are correctly separate — that's part of the convention.
For sketchy styles, render the same single path twice with small offsets and irregular stroke-dasharray — never use masking to fake roughness.


TRAINING-DATA TAKEAWAY
When generating a speech bubble, the model's reasoning should follow:

Decide body shape and dimensions.
Decide tail attachment points (two points on the body perimeter) and tail tip.
Write a single <path> that:

Starts at any point on the body perimeter
Traces the perimeter clockwise (or counter-clockwise consistently)
When reaching the first tail attachment, switches to straight lines: → tip → second attachment
Resumes tracing the body perimeter back to start
Closes with Z


Apply stroke and fill to that single path.
